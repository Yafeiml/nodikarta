# 脉络 Edge 桌面版

## 安装与打开

从项目的 GitHub Releases 下载 `Nodicarta-Edge-1.0.0-win-x64-setup.exe`，双击运行。安装器在当前 Windows 账号下安装，默认位置为 `%LOCALAPPDATA%\Programs\Nodicarta\Edge`，随包提供 .NET、Avalonia 和 SQLite。安装完成后从开始菜单打开「Nodicarta Edge」。

在主窗口底栏点「设置」。首次安装默认开启「登录时启动」：下次登录 Windows 后，Edge 静默进入托盘；点托盘图标即可打开窗口。这里也可关闭自启，选择会跨升级保留。

正式安装版默认自动检查稳定渠道。新版可用时，收回到托盘后 Edge 验证发布者签名和安装包，再切换版本。安装或启动失败时可继续使用原版本。「设置」中的应用更新开关独立于「通用 Skills」页的更新偏好。开发测试版以较高版本号迁移至首个正式版时，请运行正式安装器并确认迁移。

主窗口右上角的「语言 ▲」提供「自动」「中文」和「English」。默认的「自动」读取当前 Windows 账号的显示语言。简体和繁体中文系统都使用简体中文界面，其余系统语言使用英文。手动选择「中文」或「English」会立即切换，重启后仍然有效。再选「自动」即可跟随系统。主窗口右下角显示当前 Edge 桌面版的发行版本号。

## 接入 Core

1. 用当前 Windows 账号打开桌面版。若以前已在同一账号的默认目录配对，直接查看已有设备和项目。
2. 新设备先由管理员登录 Core 网页，在「设备管理」填写设备名称，为需要的项目选择只读或读写，生成一次性配对码。该码有效期为 10 分钟，成功兑换后即失效。
3. 在桌面版配对页面填写 Core 根地址、设备名称和完整配对码，提交后查看授权项目。同机开发可填 `http://127.0.0.1:29480`。从另一台设备测试时，填写提供 Core 服务的主机地址，例如 `http://192.0.2.10:29480`。Core 须已开放该端口并启用 HTTP；通过 HTTPS 部署时填写 HTTPS 根地址。

配对后，在设备概览顶部查看 Core 的当前连接状态。设备名用于核对本机身份，下方列出已授权项目。点「立即刷新」重新检查连接与授权，点「打开 Core」进入网页管理。

同机丢失 Edge 数据或换电脑时，可在 Core 管理页原设备名称旁点「更新设备」。在接替设备上输入完整更新码，核对 Core 后点「确认接替」。Core 在新 Edge 保存候选凭据、提交确认后停用旧身份。10 分钟内未完成确认，或管理员在确认前取消，旧设备继续工作。遇到断网，可从同一数据目录重新打开新版 Edge 恢复提交。已经提交的历史可在原设备记录中查询。新设备按继承的项目权限重新绑定自己的目录。

更换地址时，点击 Core 状态旁的双向箭头「更换 Core」，核对当前地址、本机绑定数及未发送记录数，填写目标地址和目标 Core 签发的新配对码。成功后从目标 Core 重新获取授权，并为相应项目重新添加本机目录。原身份的本机数据库会保留，原来的待发送记录、目录策略和聊天端点不会带入新身份。即使同一台 Core 只是更换了域名，也需要重新配对。旧于 1.1 的便携副本仍可能使用原设备身份，请退出旧副本。要使旧设备凭据失效，请在原 Core 的设备管理中撤销授权。

## 项目与本地目录

选择一个已授权项目，绑定本机工作目录。目录绑定由此设备保存，管理员在 Core 网页决定该设备对每个项目的访问权限。

要解除某个目录的绑定，在该目录行右侧点「解除绑定」，核对确认框中的项目名和完整路径。确认后，本机文件、同项目的其他目录以及全局 Codex 接入都会保留。原聊天下次调用项目工具时失去这条绑定的访问权限，该目录原有的聊天端点停止接收新任务。

要把目录改绑到另一个项目，先解除旧绑定，再选择目标项目，点「添加目录」，选回同一路径，从该目录新开 Codex 聊天。新绑定使用目标项目的授权。如目录以前接收指定聊天的任务，需在新绑定下重新指定接收端点。同一项目有嵌套目录时，只解除子目录的绑定，后续新聊天仍可匹配已绑定的父目录。

需要增加项目、调整读写或撤销授权时，打开 Core 网页的「设备管理」。管理员保存修改后，在桌面版刷新即可查看最新授权。设备保留原配对身份。

## 接入 AI 客户端

从托盘菜单或设备概览打开「智能体接入」。「常用客户端」列出 Codex、Claude Code、Google Antigravity、Cursor、OpenCode、DeepSeek Harness 和 Pi。首次点击「接入」，也可点「一键接入已安装」。成功后，客户端名称下显示「已接入」，Edge 会在后台维护配置。同名自定义项会保留，并在对应行提示核对。

| 接入方式 | 操作 |
| --- | --- |
| Codex | 首次点「接入」，即可为当前 Windows 用户配置 MCP 并安装通用 Skills。即使未检测到 Codex，也可以手动接入。行尾「复制」可取得 TOML。 |
| Claude Code、Cursor、OpenCode、Pi | 接入后在客户端打开绑定目录，重新加载 MCP。行尾「复制」可取得该客户端使用的 JSON。Pi 使用内置 MCP 功能。 |
| Google Antigravity | 点一次「接入」。Edge 会为已有和以后绑定的目录配置桌面连接。在 Antigravity 中从绑定目录新建聊天，直接问项目问题即可。命令行版 `agy` 也可从绑定目录启动。 |
| DeepSeek Harness | 行尾「复制」可取得 Cordis 的 YAML 补丁。重新启动 Host，从已绑定的目录启动独立 Host 可让连接使用对应项目。 |
| 其他客户端 · STDIO | 点「复制 STDIO 配置」，将 JSON 放入客户端的 MCP 设置。让客户端从聊天的工作目录启动 Edge，同一份配置可以访问不同的已绑定目录。 |

要断开某个客户端，在其行尾选择「断开接入」并确认。断开后，重启和升级都会保留这项选择。其他 MCP 服务、用户配置和通用 Skills 也会保留。手动复制给其他客户端的配置需要在对应客户端中移除。对已打开的聊天，请在客户端重新加载 MCP 或重启客户端。

「已接入」表示本机配置已就绪。客户端可能还需刷新 MCP、启用服务器或确认工作区信任。Edge 在建立连接时根据客户端提供的目录匹配最近的绑定。该目录未绑定时，只会看到 `get_edge_status`。切换项目后请从对应目录重新连接。

**Antigravity 桌面版。** 已经接入过的用户，启动新版 Edge 后会自动迁移。Edge 在已绑定目录的 `.agents/plugins/nodicarta/` 内维护项目连接，在 `.agents/rules/nodicarta-workspace.md` 内提供英文查询指引。Antigravity 从当前项目加载插件，Edge 核对该目录的绑定身份和 Core 授权，再提供相应工具。解绑立即撤销这条绑定的查询权限，同时清理 Edge 写入的插件和指引。自定义同名文件会被保留，解决冲突后，Edge 会在后台自动重试。已显示在聊天记录里的回答仍可查看。

**Antigravity 命令行。** 在项目文件夹里启动 `agy`。如果会话同时报告多个不同的工作目录，全局连接只提供状态查询；回到所需项目目录新建会话即可。[Google MCP 文档](https://antigravity.google/docs/mcp)

**按需调整单个目录。** 新目录默认按当前项目授权匹配工具。若要缩小范围，在设备概览选项目，点击「本机目录绑定」一行的「目录设置」，选好目录后点击「调整范围」，再点「保存目录设置」。可限制为知识、素材、反馈或任务，也可用「跟随项目授权」解除先前指定的工具范围。若有多个合格的任务端点，可指定接收方。保存后，收紧的范围从下一次列举或调用工具时生效。用「只读自检」核对所选目录，或在「工具目录」查看工具。

**从旧版迁移或重新测试。** 首次接入会把可识别的旧项目配置中指定的工具范围和端点移到 Edge，再移除对应的配置段和原版项目 Skills。同名自定义文件或链接会保留，需按界面提示核对。日常停用 Codex，请使用客户端行尾的「断开接入」，通用 Skills 会保留。要重测完整安装流程，可运行 `ProjectHub.Edge.Desktop.exe --disconnect-codex`。此命令也会移除本副本管理且未经修改的 Skills，保留配对、目录绑定和已保存的目录策略。

## 第一次整理项目资料

从已绑定目录打开 Codex 聊天，可以直接说下面任一句，也可以点名 `$nodicarta-init`。它会沿用该目录所属的现有项目和当前授权。

| 在聊天中说 | 整理范围 |
| --- | --- |
| 初始化项目资料 | 整理有来源的项目知识、可复用文档的索引，以及适合在项目内共享的素材。 |
| 初始化知识库 | 从文档、实现和测试记录提取可核对的项目目标、模块入口、决定和验证方法，连同来源整理成知识条目。 |
| 初始化资料库 | 为可复用文档记录相对路径、用途和摘要，按需发布选定的素材原件。 |

例如可以说：“初始化资料库，只整理 `docs/` 里的设计说明，并把 `brand/logo.svg` 作为项目 Logo 共享。”Markdown 等文档以索引条目保存。可共享原件支持 PNG、JPEG、WebP、SVG 和 PDF，每件最多 8 MiB。共享用途或归属不清的文件会列为候选，保留在本机。若项目只读，只能盘点和列出候选项；写入知识和发布素材分别需要对应的项目工具。

再次运行时，Skill 先对照已有条目和素材版本，复用相同内容，并在回复里列出新增、更新及待处理项。只想先看范围时，可说“预览项目资料初始化清单”。

要复原历史交付，可以问“上次海报用了哪一版 Logo，为什么选它？下载当时的原件”。发布方需已将海报、所用 Logo 和印样证据按版本记入决定。读取方按海报版本查决定，并按其中的 Logo 版本下载到当前绑定目录。此操作需要目录允许共享素材工具。在使用旧版 Edge 的聊天中，知识查询也可读取升级后 Core 返回的版本引用。

从绑定目录新开聊天，也可以直接描述要接着做的工作。Edge 支持按任务读取简短快照，包含相关知识版本、决定理由、证据和引用的原件。需要了解新工作应该采用什么版本时，智能体会另查项目的采纳决定。资料只记有旧版用料和新版发布时，当前选版会标为待确认。升级前的客户端也可通过中文知识搜索查询这些资料。

## 查看和更新通用 Skills

1.6.0 内置五项技能：`nodicarta-init`、`nodicarta-context`、`nodicarta-assets`、`nodicarta-inbox` 和 `nodicarta-sync`。可用中文说「用脉络找上次的决定」，其他语言可用 `nodicarta`。旧版受管 Skills 随手动更新或已启用的自动更新迁移到新名称。

自 **1.4.0** 起，五个通用 Skills 的说明统一使用英文。聊天里仍可用中文说「初始化项目资料」或「继续做上次那张宣传画」。

**1.4.1** 调整了复查后的记录方式。例如同一台电脑更新 Skills 后，智能体应在原验收条目补上设备名、核对时间和新版本，并保留先前的安装情况及依据，供另一台电脑查询。

**1.5.0** 支持按问题使用项目记忆。问“旧稿为什么这样做”时，智能体取当时的素材版本和依据；问“这次定稿用什么”时，查明当前适用的决定；问一台离线设备的状态时，只报告最后一次有依据的实测结果和时间。先更新 Core，再更新 Edge 和通用 Skills。用户无需为知识设置过期日。

**1.5.1** 查询离线设备时会核对同一设备、同一指标的多份记录，按实际测量时间比较。两份最新证据在同一时刻互相矛盾时，回复会保留分歧，等待设备恢复后复查。

**升级已接入的 Edge。** 自动更新或运行新版安装器即可。七种常用客户端共用安装目录下的固定入口 `ProjectHub.Edge.exe`。已有受管配置会从旧版本目录迁到这个入口，此后的升级继续显示「已接入」。新建的 MCP 连接使用升级后的版本。直接从解压目录运行的便携版使用该目录中的程序。

**移动桌面程序。** 一台 Windows 电脑只运行一个常驻 Edge 桌面。重复打开会唤起已有窗口。从新位置打开时，Edge 会接替当前用户原来的实例，沿用设备数据，并自动调整此前为该设备写入的智能体配置。对于自定义配置、其他数据目录或暂时无法核实的路径，Edge 会保留原有设置。

在「智能体接入 → 通用 Skills」查看已安装的数量和版本。「Edge 内置版本」是当前 Edge 随包提供的版本，记录在发行包的 `bin/skills/VERSION` 中。旧安装如果没有版本标记，会显示「旧版（未记录版本号）」。Edge 启动时和点「检查版本」时都直接比较本机文件与随包内容，无需联网。

已接入 Codex 后，受管 Skills 默认随 Edge 自动更新。可在「通用 Skills」关闭自动更新，已保存的选择会继续生效。更新会保留本机改动、链接、较新版本和先前主动移除的旧 Skill。要补装自己移除的 Skill，可运行桌面程序的 `--connect-codex` 命令。

## 日常使用与升级

单击托盘图标或再次从开始菜单打开，会唤醒已有主窗口。关闭窗口会收回到托盘，Edge 会继续检查与 Core 的连接并重试符合当前授权的待同步条目。需要完全停止时，右键托盘图标并选择退出。下次登录是否启动由登录启动项控制。

桌面版将配对身份、目录绑定、待发记录和界面语言保存在 `%LOCALAPPDATA%\Nodicarta\Edge`。与桌面版使用同一状态目录的命令行进程共用这些数据。

需要指定其他位置时，可使用 `--state "D:\EdgeData"` 或设置环境变量 `NODICARTA_EDGE_STATE`。已有的 `PROJECTHUB_EDGE_STATE` 仍可读取。

从历史桌面版迁移时，请运行正式安装包，保留原来的数据目录。新版会把旧默认目录 `%LOCALAPPDATA%\ProjectHub\Edge` 的整份数据迁入新位置，包括之前更换 Core 时保留的历史数据库。新旧位置各有一份数据时，迁移会停止并保留两份原件。自行指定的其他数据目录继续按原路径使用。

发生过旧库迁移的机器上，资源管理器可能仍显示旧的 `ProjectHub\Edge` 入口。它是指向新目录的 NTFS 联接，实际数据库位于 `Nodicarta\Edge`。备份时使用新目录即可。

可在 Windows「已安装的应用」中卸载 Nodicarta Edge。设备数据会保留。

若 Core 暂时不可达，先核对网页地址在本机能否打开，再回到桌面版刷新。若项目权限发生变化，由管理员核对该设备当前的授权。
